# PHOENIX Prompt Library

Last updated: 2026-08-03
Status: approved

外部Codexへ渡す承認済み短縮テンプレート。現在の依頼が常に優先され、必要なテンプレートだけを使う。保存済み共通前提は長文で重複記載しない。

## T-001 作業開始
```text
AGENTS.md と knowledge/00_INDEX.md の導線に従って承認済み記憶を確認してください。現在の依頼を過去の記憶より優先し、今回は「[目的]」だけを扱ってください。
```

## T-002 正本ワークスペース限定
```text
CURRENT_STATE.md で正本を確認し、その正本だけで作業してください。ブラウザWork、自動handoff、別worktree、Documents\Codex、別コピーへ送らないでください。ツール・権限・ワークスペースは確認後に報告してください。
```

## T-003 Python環境
```text
Pythonは正本の .venv\Scripts\python.exe を最優先してください。代替環境、PATH変更、パッケージ追加は無断で行わず、必要なら理由・絶対パス・依存関係差を先に報告してください。
```

## T-004 通知前確認
```text
通知前に当日レポートとデータ基準日時を確認してください。古い結果を現在結果として送らず、PAPER、Orders submitted: 0、Guardian、Position Reconciliation、Fail Safeを維持してください。
```

## T-005 再試行判定
```text
実行前に「この操作で新しく分かること」を1文で確認してください。同じ失敗条件のまま再試行せず、条件が変わらなければ停止して報告してください。
```

## T-006 作業終了報告
```text
終了時は変更ファイル、テスト結果、保護対象、Git操作、外部接続だけを簡潔に報告してください。未実施項目は未実施と明記してください。
```

## T-007 完了報告＋保存＋次指示
```text
同じ返答に、1. 完了報告、2. ユーザーが許可した保存コマンド、3. 次の指示書を順にまとめてください。別返答や自動handoffへ分割しないでください。
```

## T-008 クレジット節約
```text
1タスク1目的で進め、承認済み記憶を参照して共通前提を重複記載しないでください。新情報のない確認、同条件の再試行、無関係な調査、不要な全体テストを行わないでください。
```
