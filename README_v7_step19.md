# PHOENIX v7 Step19

Step19は、実売買を開始する機能ではありません。30万円から始める運用計画について、固定費・取引費用・税引当を控除した成績だけを使い、限定パイロット候補と条件付き20万円追加の可否を判定する安全ゲートです。

## 固定した資金計画

- 初期資金: 300,000円
- 条件付き追加資金: 200,000円
- 最大資金: 500,000円
- 追加資金は利益に数えない
- 追加資金だけではリスク計算の元本を300,000円から増やさない
- 入金とリスク上限の拡大には、それぞれ別の明示承認が必要

## 費用と分配

- ChatGPT、Excel、電気代等の固定費: 7,000円/月
- 楽天証券の実際の手数料コースが確認できるまでは、1約定1,070円を保守的に予約
- スリッページはシグナル価格から約定価格への不利方向だけを執行品質指標として記録する。実約定価格ベースの損益に既に反映されるため二重控除しない
- 課税区分が確認できるまでは、確定純利益の20.315%を保守的に税引当
- 生活資金の暫定比率: 費用・税引当後の確定利益の20%
- 安全上限: 30%
- 含み益、外部入金、未回復損失は分配原資にしない
- 月末照合、High-Water Mark、手動承認が未完了なら実際の分配額は0円

計算の基本形は次のとおりです。

```text
戦略純確定損益
  = Step19以後の確定損益
  - 手数料の実額または保守予約

不利方向スリッページ
  = 実約定価格に反映済みのため分析値として別表示

事業純利益
  = 戦略純確定損益
  - 月7,000円の固定費
  - 税引当
```

## 会計証拠

Paper Broker stateはv2へ移行します。v1時点の現金、保有、確定損益、処理済み注文は会計基準としてだけ保存し、過去約定として加点しません。

Step19以後の約定は、口座残高・保有更新と同じatomic JSON更新に次を保存します。

- 注文IDと約定ID
- 売買、銘柄、数量
- 要求価格と約定価格
- 約定代金
- 手数料
- 現金増減
- 売却原価と確定損益
- 不利方向スリッページ
- canonical SHA-256

欠損、重複、非有限値、負費用、hash不一致、現金・損益・保有の照合不一致はfail closedです。

## 限定パイロット候補条件

候補ゲートは、少なくとも次をすべて要求します。

- 異なる東証5取引日のRakuten RSSリアルタイムshadow証拠
- 3件の重複しない監査済みshadow約定
- Step17履歴検証、Step18候補契約、市場データ、保有、約定、会計の全ガード
- 現物口座の確認
- 1日1回の新規BUY送信試行
- 確認済み1単元
- single-useの手動承認
- リスク縮小SELL専用経路
- 楽天証券の実際の手数料コースと税区分の確認

現在はRakuten RSS/Excel VBA、single-use手動承認、実口座の手数料・税区分、1日1BUYと安全SELLの実行境界が未実装または未確認です。そのためStep19は`NOT_READY`を返します。

`READY`になっても、これは候補資格だけです。実売買、自動昇格、自動入金、リスク自動拡大、生活費送金は一切実行しません。

## 2026-07-23 最終安全レビュー反映

- 約定時刻はJST（`+09:00`）、Step19基準以後、broker更新時刻以前、時系列順を必須化。
- 実約定価格ベース損益にスリッページを二重控除せず、スリッページは執行品質指標として記録。
- 税引当は年ごとの正の確定損益へ20.315%を適用し、未確認の前年損失繰越を加点しない。
- 楽天手数料はコース名・口座証拠hash・料金表hashを確認できない限り1約定1,070円を引当。
- 条件付き20万円は、5取引日・3約定・全費用後利益プラス・固定費回収・損失回復・High-Water Mark・最大DD 10%以内・独立台帳照合を必須化。
- Shadow/Pilot証拠は公式JPX取引日、未来日禁止、重複なし、session/root SHA-256、検証済みJPXカレンダーhash、lifecycle/economics双方の約定IDと1対1リンクを必須化。
- lifecycle/economicsの1対1リンクはIDだけでなく、注文ID、銘柄、売買、数量、約定時刻、約定hashまで完全一致を必須化。
- 楽天口座プランと料金表は、設定欄へ任意のhash文字列を書くだけでは確認済みにならない。リポジトリ内の証拠ファイル本体と、その実測SHA-256が一致した場合だけ実料金を採用する。
- readiness gate自身がStep19 staged pilot gateを再計算し、RSS、single-use手動承認、口座・会計照合、安全SELLが未確認なら昇格候補にしない。
- `live_trading_enabled`、自動昇格、自動入金、自動リスク拡大、外部送金は引き続き常時false。

## 8時通知の市場データ鮮度修正

2026-07-23の調査では、通知ファイル自体は当日生成されていましたが、株価基準日は2026-07-14、市場キャッシュ最終日は2026-07-17でした。scannerがcache保存日時だけを見て当日データと判断していたためです。

- scannerは各銘柄の最終市場日を、実行時点で直近完了したJPX現物取引日と完全一致させる。固定日数の猶予は使わない。
- scanner/reportは日経225の225銘柄をすべて要求し、重複、欠落、一部取得のレポート化を拒否する。銘柄集合hashを通知まで引き継ぐ。
- notifierは当日レポートのrun ID、生成時刻、銘柄数、JPXカレンダー証跡、SHA-256を通知直前に照合する。古いデータ、別実行の再利用、改変、生成から4時間超過ならLINE/Discord送信前にfail closedする。
- AI判定にもsource run ID、元レポートhash、AI出力hash、銘柄数、学習・最適化入力hashのmanifestを持たせ、異なる実行結果の混在を通知前に拒否する。
- 日次スキャンが空または失敗した場合は非ゼロで終了し、古い当日名レポートを後続処理へ渡さない。
- Price Monitorは連続監視ではなく1回実行に限定し、Learning Engineが失敗した場合も通常通知へ進まない。
- 空の学習データで`KeyError: dimension`になったLearning Engineを、空schemaを返して安全に継続するよう修正。
- データ供給元が更新できない日は、古い価格を新しい通知として再送しない。楽天RSS接続までは外部データ取得失敗が運用上の残存ブロッカー。

## 次段階の資産設計

日本株パイロットの検証と並行して、将来の円・ドル・配当運用に次の会計境界を設けます。これは現時点で実資金取引を有効化するものではありません。

- 円現金、ドル現金、証券時価、未収配当を別台帳にし、入出金と利益を混同しない。
- 為替換算損益、売買損益、配当、国内外源泉税、手数料を別科目で保存する。
- 配当利回りだけでなく、減配、配当性向、フリーキャッシュフロー、権利落ち、為替変動を検証する。
- 生活資金への分配は、固定費、税引当、未回復損失、High-Water Markを満たした確定余剰だけを対象にする。
- 米国株・ドル資産は、日本株の現行リスク枠を共有せず、別の承認済み上限とpaper/shadow証拠を要求する。
